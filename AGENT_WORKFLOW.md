# Процесс агентной разработки

Документ описывает координацию Custom Agents Kimi Code для этого проекта. Он не добавляет функции ERP и не заменяет ТЗ или журнал решений.

## Роли

| Агент | Назначение | Основная граница |
| --- | --- | --- |
| `orchestrator` | Декомпозиция, назначение, контроль, интеграция | Не выполняет самостоятельно крупную реализацию |
| `architect` | Архитектура, границы, контракты, анализ зависимостей | Документация и проектные решения, не прикладной код |
| `backend` | Kotlin/Ktor, сценарии, API, серверные правила | `server` и согласованные контракты `core` |
| `frontend` | Compose, Kotlin/Wasm, состояние и UX | `app`, не серверная бизнес-логика |
| `database` | PostgreSQL, миграции, jOOQ, индексы | Схема и persistence, не UI |
| `qa` | Тесты сценариев, API, прав и интеграции | Тесты и отчёты, не исправление production-кода |
| `security` | Права, аудит, сессии, файлы и security-тесты | Только согласованный security-объём |
| `reviewer` | Независимый анализ изменений | Только чтение, без исправлений |
| `devops` | Сборка, конфигурация, развёртывание, CI и восстановление | Не выполняет удалённые действия без отдельного поручения |

Все профили находятся в `.kimi-code/agents/`. Это определения ролей, а не постоянно запущенные процессы.

## Рабочий цикл

1. **Выбор задачи.** Оркестратор читает `TASKS.md`, проверяет статус и зависимости.
2. **Проверка требований.** Ссылки на утверждённые решения обязательны. Если задача зависит от предложения или открытого вопроса, она остаётся `BLOCKED`.
3. **Декомпозиция.** Формируются независимые части с явными владельцами файлов и критериями.
4. **Согласование контрактов.** До параллельной реализации фиксируются DTO, API, схема БД и миграционная граница.
5. **Исполнение.** Каждый агент работает только в назначенном объёме. Специалисты не делегируют дальше.
6. **Проверка исполнителя.** Выполняются проверки из задачи; введённые данные и ошибки не скрываются.
7. **Независимый review.** `reviewer` получает список изменений, требования и результаты проверок, но не исправляет код.
8. **Интеграция.** Оркестратор сам повторяет необходимые сборки, тесты и сквозной сценарий.
9. **Завершение.** Только после успешной интеграции обновляются статус и фактический результат в `TASKS.md`.

## Правила параллельности

Можно выполнять параллельно независимые исследования, review и изменения без пересечения файлов. Нельзя параллельно:

- редактировать один файл;
- создавать или менять общие миграции;
- несогласованно менять общие DTO/API;
- менять зависимые участки без общего контракта;
- интегрировать результат, пока обязательные проверки не завершены.

`AgentSwarm` не является режимом по умолчанию: он доступен только после явного включения swarm-режима пользователем.

## Изоляция

При наличии Git используйте отдельные ветки или worktree для крупных независимых работ. Перед интеграцией проверяются полный diff, отсутствие чужих удалений и обязательные проверки.

Сейчас в рабочем каталоге нет `.git`. Ветки и worktree недоступны; Git не инициализируется этим процессом автоматически. До появления репозитория используются последовательная интеграция и запрет параллельной записи в общие файлы.

## Навыки

`karpathy-guidelines` установлен на пользовательском уровне в `~/.agents/skills/karpathy-guidelines/SKILL.md` и доступен агентам через каталог Skills. Не копируйте его в проект или отдельные промпты. Профиль вызывает навык при написании, review и рефакторинге кода; для тривиальных задач применяется его оговорка о разумном балансе тщательности и скорости.

## Формат поручения агенту

Каждое поручение содержит:

- цель и идентификатор задачи из `TASKS.md`;
- ссылки на утверждённые требования;
- уже подтверждённые факты и точные пути;
- разрешённые файлы/модули и запрещённые изменения;
- зависимости и владельцев смежных контрактов;
- критерии готовности и обязательные проверки.

## Формат отчёта агента

Последнее сообщение субагента является самостоятельным результатом для вызывающего:

1. Что сделано.
2. Изменённые файлы.
3. Проверки и их фактический результат.
4. Что не сделано и почему.
5. Оставшиеся риски и блокеры.

## Запуск оркестратора

В новой CLI-сессии из корня проекта после появления Git-метаданных и обнаружения project-level агентов:

```bash
kimi --agent orchestrator
```

Независимо от наличия Git можно выбрать файл явно:

```bash
kimi --agent-file .kimi-code/agents/orchestrator.md
```

Оба варианта относятся только к созданию новой сессии. При возобновлении сохранённой сессии флаги выбора агента не используются. Начальное поручение: «Прочитай AGENTS.md, TASKS.md и docs/decisions.md. Проверь доступные задачи, не начинай заблокированную реализацию».

Ограничения инструментов и разрешённые типы субагентов задаются frontmatter каждого профиля. Правила доступа к опасным операциям остаются отдельным механизмом разрешений Kimi Code.
