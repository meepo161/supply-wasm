# UX-аудит ERP «Авиаагрегат-Н» — 22.11.2026

Источники: живое приложение `http://localhost:8081` (экран входа, десктоп 1440×900 и мобильный 375×812), обзор кода всех 15 вкладок в `app/shared/src/commonMain/.../ui` и поведение API, на котором стоят экраны (smoke-набор).

**Ограничение.** Обход вкладок после входа в браузере не выполнен: вход под аварийной учёткой заблокирован правилами доступа агента, а других тестовых учётных данных для dev-базы нет. Для живого обхода нужна тестовая учётная запись dev-базы (или вход пользователя в панели браузера). Выводы по внутренним экранам сделаны по коду и поведению API.

## Что сделано хорошо

- Экран входа аккуратно адаптируется под 375 px: форма не обрезается, кнопки крупные.
- Меню формируется по правам (`NavigationDestination.isVisibleTo`), а сервер независимо закрывает те же разделы (подтверждено smoke-сценарием: 403 на 7 закрытых разделах).
- Почти все отмены документов (заказ, поставка, потребность, маршрут согласования, этап проекта) идут через диалог с причиной.
- Пустые состояния оформлены карточками с пояснением («Этапов нет — список этапов заказа пуст»).
- Двойной клик «Подтвердить выдачу» безопасен благодаря ключу идемпотентности.

## Рекомендуемый порядок

1. UX-01 + AUDIT-01: одна правка в `StatusPages` и словарь кодов на клиенте сразу убирают 500 и английские тексты.

3. UX-02 и UX-03: ввод дат и подтверждения в BOM.
4. Остальное — по мере работы над соответствующими вкладками.
