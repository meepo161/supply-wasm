# Обзор экранов, десктоп — 22.11.2026

Сборка: текущее состояние основной папки на `develop` (506d324) вместе с незакоммиченными правками, включая новую таблицу `ErpDataGrid`/`ErpPaginationBar`. Окно 1440×900, вход администратором, демо-данные из `scripts/seed_demo.py` (база `erp_demo`): 3 проекта, 6 задач, склад, BOM, производство, поставщики, заказ, счёт, документы.

Общие проблемы, которые повторяются на многих экранах, вынесены в первый раздел; в разделах экранов они не дублируются.

## 0. Общее (все экраны)

1. **ID вместо названий.** «Склад ID 1», «Номенклатура ID 5», «Род.ном. 1», «Утвердил 3», «Проект 2», «Ревизия BOM 1», «Потребности #1». Для пользователя это бессмысленные числа: везде нужно показывать код и наименование, а ID скрыть.
2. **Служебные поля на виду.** Колонки «ID» рядом с «#», «Версия 0/2/3» в таблицах, шапках и карточках. Это внутренние счётчики для защиты от конфликтов, пользователю они не нужны.
3. **Даты в ISO** (`2026-11-19`, `2026-12-31T23:59:59Z`) вместо `19.11.2026`. Время «01:00» появляется из-за сдвига часового пояса при хранении даты как полуночи UTC.
4. **Непереведённые значения:** `NORMAL`, `SUPPLIER`, «RUB» вместо «₽», «100.00 %», количества с четырьмя знаками («1200.0000»).
5. **Таблицы в карточках.** Новая `ErpDataGrid` хороша для реестров, но внутри карточек (этапы, позиции заказа) на 2–3 строки её панель (поиск, «Стандарт», «Колонки», постраничный вывод) занимает больше места, чем данные, и видна только часть строк. Нужен компактный режим без панели и пагинации.
6. **Две таблицы в продукте.** 11 файлов экранов по-прежнему вызывают старую `Un7KCMPDataGrid` напрямую: склад (часть), приёмка, BOM, поставщики, заказы и др. Внешний вид и поведение таблиц разные.
7. **Двойной поиск.** На «Поставщиках» поиск страницы и поиск таблицы стоят подряд; на «Задачах» плашки фильтров плюс поиск по таблице плюс глобальный поиск.
8. **Меню.** «Задачи» и «Проекты» дублируются в «Избранном» и «Работе»; 15 пунктов не помещаются в 900 px и меню прокручивается. Пункт под курсором становится светлым с белым текстом — нечитаемо.
9. **Цвета статусов.** Словарь `statusCellColorOrNull` не знает «Активна», «Сверен» и др., поэтому часть статусов не окрашена. Цвет лучше брать из перечислений статусов, а не угадывать по тексту ячейки.
10. **Просрочка нигде не подсвечивается** (задачи, сроки, счета): срок в прошлом выглядит так же, как будущий.

## 1. Главная

1. Для руководителя и администратора счётчики считают только личные задачи: «0 просрочено» и «Все задачи под контролем. Отличный день!» при реальной просроченной задаче. Нужен режим «по компании / по подразделению» или честная подпись «ваши задачи».
2. Приветственная шапка занимает треть экрана почти без информации; лучше сжать её до строки и отдать место рабочим блокам.
3. Баннер «Браузерные уведомления отключены» стоит на самом видном месте; его стоит перенести в профиль или показывать один раз со «скрыть».
4. Метки «чисто» на всех четырёх плитках повторяют ноль и не несут смысла.
5. Не хватает быстрых действий (создать задачу, принять поставку, загрузить счёт) и блока «требует моего решения»: согласования, сверки счетов, приёмки.

## 2. Задачи — реестр

1. Нет номера задачи (T-2026-…), по которому её ищут и обсуждают.
2. Срок в прошлом не выделен; нужны цвет и метка «просрочено N дн.», а также сортировка по сроку по умолчанию.
3. Колонка «Приоритет» у всех «Обычный» — шум; показывать приоритет только если он отличается от обычного.
4. Проект обрезан («P-2026-00003 · Стенд испытаний трансформат…»): номер проекта съедает место, лучше показывать название, а номер в подсказке.
5. Три слоя фильтрации (плашки статуса, плашки области, поиск таблицы) — свести к одной строке фильтров с понятным «сбросить».
6. Нужна быстрая смена исполнителя и статуса из строки или массовые действия по выделенным строкам.

## 3. Задача — карточка

1. Заголовок экрана «Задача»; название задачи мелким шрифтом. Номер и название должны быть главным заголовком.
2. Просроченный срок не выделен; статус «Назначена» без пояснения, что ждёт исполнителя.
3. Поле «Версия 0» и даты в ISO в «Сроках и истории».
4. ФИО исполнителя обрезано в верхней строке при свободном месте справа.
5. Кнопка «Отправить» в шапке неочевидна (это «поделиться/переслать»), её стоит назвать прямо.
6. Если у пользователя нет действий по задаче, стоит писать, кто и какое действие сейчас должен сделать («Ждёт: Кузнецова — взять в работу»).

## 4. Проекты — реестр

1. «Участники 0» у всех проектов, хотя в карточке «Участников 6» — ошибка подсчёта.
2. Нет колонки «Руководитель» и прогресса (закрыто задач / всего, просрочено).
3. Название и срок обрезаны, а «Тип» («Разработка по з…») занимает ширину; тип можно сократить или убрать в фильтр.
4. Вкладки статусов показывают только существующие («Все», «Черновик»); полезнее постоянный набор «В работе / Черновики / Завершённые».
5. Все три проекта «Черновик», хотя по ним идут задачи и производство, — подсказка «Откройте проект» рядом со статусом.

## 5. Проект — карточка

1. Обзор — список «Параметр: значение» сплошным текстом; лучше шапка с ключевыми показателями (сроки, прогресс, риски) и плитками.
2. Числа в блоке показателей прижаты к правому краю далеко от подписей — в широком окне читать трудно.
3. «Версия: 0» на виду.
4. Нет вкладки или блока «Производство», хотя по проекту есть производственный заказ; нет связки с BOM изделия проекта.
5. Нет кнопок основных действий в обзоре (открыть проект, добавить задачу, добавить участника).

## 6. Чат

1. Список забит чатами задач без сообщений («Сообщений пока нет»); их стоит скрывать до первого сообщения или вынести в отдельный фильтр.
2. Номер задачи «T-2026-00001 — Выпустить К…» съедает название; название первым, номер мелко.
3. Второй ряд фильтров обрезан («Архи…») — нужен перенос или меню «ещё».
4. Список узкий (~280 px), справа большая пустая область; на 1440 px можно расширить список или показывать сведения о задаче.
5. Разделитель даты в ISO («2026-11-22»); «Отправить» в шапке чата на деле «переслать».

## 7. Склад — остатки

1. Вместо склада и номенклатуры — ID; нет кода, наименования и единицы измерения — таблицей невозможно пользоваться.
2. Количества с четырьмя знаками («1200.0000»).
3. Пустые колонки «Партия», «Серия» занимают место — скрывать по умолчанию, если данных нет.
4. Нет подсветки позиций ниже минимального остатка и резерва рядом с физическим количеством в строке.
5. Два меню (основное + меню склада) занимают ~40% ширины; меню склада можно сделать вкладками сверху или сворачиваемым.

## 8. Склад — приёмка

1. Блок «Открыть приёмку» + «ID приёмки» с ручным вводом номера — технический; хватит списка с поиском.
2. Статусы «Черновик / Проведена» оформлены синим как ссылки и путаются с «Открыть».
3. Счётчик «Приёмка 7» считает все документы, а полезно — ожидающие действия склада (1).
4. Список не переведён на новую таблицу: нет сортировки, фильтра по поставщику и дате.
5. Для приёмки по счёту стоит сразу показать поставщика, позиции и срок, а не только номер счёта.

## 9. Производство

1. В списке заказов нет изделия, количества и прогресса; статус обрезан («В производст…»).
2. «Ревизия BOM 1» (ID вместо «A»), «Приоритет NORMAL», время «01:00».
3. Таблица этапов из 3 строк показывает 2 и несёт полную панель таблицы; этапы удобнее шкалой шагов (выполнено → текущий → далее).
4. «Этап» и «Тип» дублируют одно и то же значение.
5. Материалы заказа (из BOM) не видны без прокрутки; нужен блок «Материалы: план / выделено / израсходовано» рядом с этапами.

## 10. Спецификации (BOM)

1. **Состав ревизии нечитаем:** «Род.ном. 1», «Доч.ном. 2» — нужны код и наименование компонента; это главный экран конструктора.
2. Количества «1.0000», нет дерева уровней (родитель → дети).
3. «Заменить» — главная синяя кнопка, хотя это действие выводит ревизию из работы; главной должна быть безопасная кнопка, опасная — второстепенной.
4. В ревизиях «Утвердил 3» (ID), нет даты утверждения и причины изменения; действующая ревизия не выделена в списке.
5. Раздел называется «Спецификации (BOM)», а номенклатура живёт в «Складе» — нужен переход к номенклатуре или общий справочник.

## 11. Поставщики

1. Два поля поиска подряд (страница и таблица).
2. В списке нет статуса проверки и ИНН — главных признаков для выбора.
3. Тип «SUPPLIER» без перевода.
4. В карточке длинный столбец пустых «—»; пустые реквизиты свернуть с призывом «Заполнить».
5. Нет истории заказов, счетов, рекламаций и оценки поставщика в карточке.

## 12. Заказы поставщикам

1. Поле «Счёт: —» при зарегистрированном счёте: старое текстовое поле не связано со счетами — показывать счета по заказу.
2. Таблица позиций в карточке показывает 1 строку из 2 и полную панель таблицы.
3. «Отменить» стоит вплотную к «Править»; опасное действие отделить и сделать второстепенным.
4. «версия 3» в шапке, «Потребности #1».
5. Итоги «13 470 RUB» — «₽»; добавить остаток к поставке и оплате.

## 13. Счета поставщиков

1. Левая колонка почти пустая; список удобнее таблицей с суммой, сроком действия и статусом склада.
2. Нет индикатора «до истечения срока N дн.» и подсветки истёкших.
3. Файл счёта только скачивается — нужен просмотр PDF рядом с реквизитами для сверки.
4. «предоплата 100.00 %», «версия 2» в шапке.
5. Результат сверки «расхождений нет» стоит внизу; статус сверки лучше показывать в шапке карточки.

## 14. Потребности

1. «Проект 2» — ID вместо названия проекта.
2. Нет состава (что и сколько нужно) и процента покрытия — главная информация потребности.
3. Нет инициатора и срока «до требуемой даты N дн.».
4. Кнопка «Объединить потребности» видна всегда, хотя выбрать строки нельзя.
5. Даты в ISO.

## 15. Документы

1. Не видно файла (тип, размер) и номера актуальной версии.
2. Нет связанного объекта (счёт → заказ, протокол → изделие).
3. Нет фильтра по типу документа и владельцу.
4. Заголовок «Конфиденциально…» и ФИО владельца обрезаны.
5. Все документы «Черновик» без подсказки, что нужно для согласования.

## 16. Аналитика и календарь

1. Значения «6 / 1» через косую черту непонятны без расшифровки — по отдельной плитке на показатель.
2. Очереди подразделений все нулевые, хотя открытые задачи есть (проектные задачи не учитываются) — вводит в заблуждение.
3. «OpenAPI (JSON)» в выгрузках для пользователя — убрать в раздел для администратора.
4. «Импорт CSV» стоит среди кнопок экспорта — отдельное действие с предупреждением.
5. Нет динамики и графиков (задачи по неделям, просрочка, закупки).

## 17. Уведомления

1. Пустой экран без фильтров по типу и периоду.
2. Нет действия «отметить все прочитанными».
3. Кнопка «Включить push» дублирует баннер с главной.
4. Нет группировки по объекту (задача, счёт, заказ).
5. Нет настроек уведомлений прямо здесь (сейчас они только в профиле).

## 18. Администрирование

1. Колонка «Права» у всех «—», хотя роли назначены; показывать роли.
2. ФИО обрезаны; нет даты последнего входа и признака блокировки.
3. Email «—» у всех без подсказки заполнить.
4. «Активен: Да» лучше переключателем прямо в строке.
5. Нет фильтра по подразделению и роли.

## 19. Профиль

1. Делегирование вводится числом «ID заместителя» — нужен выбор сотрудника из списка.
2. Дата делегирования в формате `2026-12-31T23:59:59Z` — нужен календарь (компонент `ErpDateField` уже есть).
3. Настройки уведомлений стоит дополнить выбором событий (назначение, согласование, счёт).
4. Нет списка активных сеансов и выхода на других устройствах.
5. Смена пароля внизу страницы без индикатора надёжности.
