# План: карточка номенклатуры (товара)

Статус: реализовано 24.11.2026 по решению `D-63`. Задача: `NSI-001` (`TASKS.md`).
Отличия от плана: часть пробелов (мин./страховой запас, пересчёт единиц, аналоги, удаление штрихкодов, where-used) уже была в `develop` (V37, V41), поэтому миграция получила номер `V44` и только дополняет их.
Решения пользователя: одна карточка для всех типов номенклатуры (у изделия
добавляются свои блоки), полный объём с визуальной проверкой, все вкладки видны
каждому, у кого есть доступ к карточке.

Основание: ТЗ §8.2 (атрибуты), §8.3 (остатки), §10.2 (изделие), §10.5 (аналоги),
§10.6 (применяемость); `PROGRESS.md` BOM-01/02/18/20.

## 2. Состав карточки

**Шапка:** изображение, код, наименование, артикул, тип, категория; плашки
«Архив», «Партии», «Серии», «Ниже страхового запаса»; сводка остатков
(доступно / физически / резерв / ожидается) в базовой единице; действия
«Редактировать», «Архивировать» (с проверкой ссылок).

**Вкладки:**
1. **Обзор:** описание, производитель, модель, характеристики, масса, габариты,
   единицы и коэффициенты, штрихкоды.
2. **Остатки:** 7 видов по §8.3; разбивка по складам и ячейкам, по партиям и сериям;
   график остатка за 90 дней, восстановленный по журналу движений.
3. **Снабжение:** мин./страховой запас, срок поставки, условия хранения,
   допустимые склады, аналоги.
4. **Резервы:** активные и закрытые резервы с основанием (проект, задача, задел)
   и историей.
5. **Движения:** журнал `stock_movement` с документом-основанием, автором,
   фильтром по типу и периоду.
6. **Применяемость:** BOM-ревизии, изделия, потребности, заказы поставщикам,
   экземпляры изделий.
7. **Изделие** (только если номенклатура связана с моделью): статус разработки,
   конструктор, технолог, ревизии BOM со ссылкой в модуль BOM.
8. **Документы и изображения:** галерея и связанные документы DMS.
9. **История:** записи `audit_log` по номенклатуре.

Вкладка без данных показывает пустое состояние с пояснением, а не прячется
и не заполняется заглушками.

## 3. Этапы реализации

Выполняются последовательно: этапы 1–2 меняют общие миграции и DTO.

### Этап 1. Схема и модель (сервер, core)
- Миграция `V30__nomenclature_card.sql`:
  - поля `nomenclature`: `article`, `manufacturer`, `model`, `category_id`,
    `weight_kg`, `length_mm`, `width_mm`, `height_mm`, `min_stock`,
    `safety_stock`, `lead_time_days`, `storage_conditions`, `product_model_id`
    (UNIQUE, nullable);
  - `nomenclature_categories` (иерархический справочник);
  - `nomenclature_attributes` (характеристики ключ–значение–единица);
  - `nomenclature_unit_conversions` (единица, коэффициент к базовой);
  - `nomenclature_allowed_warehouses`;
  - `nomenclature_analogs` (аналог, коэффициент, условия, требует согласования);
  - `document_links.nomenclature_id` + обновление CHECK «ровно одна цель».
- Пересборка jOOQ, расширение `NomenclatureDto`, новые DTO карточки.

### Этап 2. API
- `GET /api/wms/nomenclature/{id}`: карточка целиком (атрибуты, единицы,
  штрихкоды, аналоги, склады, связь с моделью).
- `PUT /api/wms/nomenclature/{id}`: изменение с проверкой `version`
  (конфликт → 409), аудит с diff полей.
- Штрихкоды: `POST`/`DELETE /nomenclature/{id}/barcodes` (закрывает BOM-02).
- `GET /nomenclature/{id}/stock-summary`: 7 видов остатка по единому правилу
  с разбивкой по складам.
- `GET /nomenclature/{id}/movements?from&to&type&page`.
- `GET /nomenclature/{id}/usage`: применяемость (закрывает BOM-18).
- `POST /nomenclature/{id}/archive`: отказ при активных ссылках с их перечнем
  (закрывает BOM-20).
- `GET /nomenclature/{id}/history`: из `audit_log`.
- Изображения через существующий `AttachmentRoutes`, документы через `DocumentRoutes`.
- Категории: `GET/POST /api/wms/nomenclature-categories`.
- Тесты `NomenclatureCardRoutesTest`: права (read/manage), 404, конфликт версии,
  расчёт сводки остатков (карантин/брак/в пути/ожидается), архив с активными
  ссылками, пагинация движений.

### Этап 3. Клиент (Compose/Wasm)
- `WmsApiClient`/`WmsRepository`: новые методы.
- `ui/wms/card/`: `NomenclatureCardScreen`, `NomenclatureCardViewModel`, вкладки
  в стиле `ProjectDetailScreen`/`ProjectTabs`.
- Переход в карточку из списка номенклатуры и из строк остатков, резервов и BOM.
- Диалог редактирования; обработка 409 с предложением перезагрузить.

### Этап 4. Проверка и документация
- Сборка и тесты по `docs/development.md`.
- Визуальная проверка в браузере на реальных записях: создать позицию с
  партиями, провести приёмку, резерв, перемещение в пути, перемещение в
  карантин; убедиться, что каждая вкладка показывает реальные данные; проверить
  пустые состояния, архив с активной ссылкой, конфликт версии в двух вкладках.
- Ревью профилем `reviewer`.
- Обновить `PROGRESS.md` (BOM-01/02/18/20, строки §8.2–8.3), `docs/features.md`,
  `TASKS.md`.
